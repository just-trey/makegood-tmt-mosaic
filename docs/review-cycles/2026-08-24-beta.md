## 3. Ranked action list

### Tier 0 — Correctness

Twelve, deduped. Every one has a driven repro in a lens file. **Nine are pre-existing
and unrelated to the beta narrowing**; that is flagged per item, because it changes
what this release is answerable for.

**T0-1. Cancelling the restore confirm exports the wrong part under the right filename.** _(High)_
Lenses: `not-ready` NR-1. Also observed by `edge-cases` T1-5 and `walkthrough` F1 from the copy side.
Restore a footrest session, Cancel the second confirm the app raises on top of it, and the
dropdown reads Footrest while the scene holds the wheel. Export downloads
**`mosaic-footrest.3mf` containing Top / Bottom / Cap**, 2 plates, 4 filaments, no warning:
a complete, valid, printable wheel under the footrest's name.
Pre-existing. `docs/tech-debt.md` records the cause and **understates it twice** — it says
"blocks nothing on the wheel, footrest or hubcap" (it blocks both non-boot kinds) and never
mentions the filename. **That entry was written during this release and was wrong.**
Never seen in four rounds of code review or in the branch's own driven check, because
`newPage()`'s hook auto-accepts confirms. `not-ready` removed the hook.
Change: clear `state.assembly.parts` before `asmLoadFullAssembly()` in `applyRestoredSession`,
matching the fallback branch beside it. Effort: **S**.

**T0-2. The saved session is destroyed three ways, all silent and permanent.** _(High)_
Lens: `edge-cases` T0-1, T0-2, T0-4 — one root cause.

- Opening any `?kind=` URL deletes it. Measured 1128 bytes → null, unrecoverable.
- The restore banner deletes the session it is offering, ~1s into the boot that shows it. Banner visible at t+1s with storage intact, storage null at t+7s. A second reload loses the work.
- A failed restore deletes it with nothing on screen.

Cause: the default boot's bare-part rebuild reaches `saveSession()` with no artwork and calls
`clearSavedSession()`. `savedSessionIsOnHiddenKind()` is the guard that exists for exactly this
and only covers hidden kinds. Pre-existing.
Change: hold the session while an unanswered banner is showing, and whenever the boot was told
not to offer it. Effort: **S–M**.

**T0-3. Assembly mode has no maximum-depth clamp and no warning.** _(High)_
Lens: `edge-cases` T0-6. Depth 20mm and 9999mm on the wheel both build and export with **zero
warnings**; flat mode clamps and warns for the same input. `geometry/depth.ts`'s own comment
states the contract as "a zero is raised **and a too-deep value clamped**, so both warn" — the
second half is false for every part a user can now select. CLAUDE.md's named failure shape: a
warning that never fires. Pre-existing, but the beta narrowing removed the only mode where the
clamp existed, so it is now the shipped behaviour for everything.
Change: give assembly mode the clamp-and-warn, asking the mapper for the depth it can cut.
Effort: **M**. **Opus** — `src/geometry/`.

**T0-4. Hubcap exports write no prime-tower position while the UI says they do.** _(High)_
Lens: `not-ready` NR-2. 7 of 9 hubcap exports, **including the default 220mm hubcap on the
Bambu H2D from a cold load**, carry no `wipe_tower_x/y` at all on a 4-filament print. The pill
says "so it was parked at (270, 240)"; nothing in the file says that. The help says "It exports
centred with the tower in the freest corner"; it does not. Wheel and footrest carry towers on
all three beds. Pre-existing.
Change: write the computed position on every plate that needs a tower, or stop claiming one was
written. Effort: **M**. **Opus** — `src/export/`.

**T0-5. Every export hardcodes Generic PETG in all four slots.** _(High)_
Lens: `maker-workflow-review` M5. `filament_type: rep('PETG')` (`threemf.ts:202`) and
`filamentId: 'Generic PETG'` at `printers.ts:47/61/75`, with no selector anywhere in the app. A
volunteer printing PLA gets a project claiming PETG and a PETG-derived temperature profile, and
the slicer proceeds. Pre-existing.
**One correction to the finding**: it says "no mention anywhere". The README does say it. The
app does not, which is where it matters. Effort: **M** for a selector, **S** for saying so.

**T0-6. A restore that throws part-way wedges the app until F5.** _(High)_
Lens: `edge-cases` T0-3. Seven single-field corruptions all pass `isPersistedSession()` (it checks
only `version`, `savedAt`, and two array types); three leave the app unable to build at all, with
a raw `TypeError` in the warnings panel — `Rebuild failed: Cannot read properties of null
(reading 'asm:#0000cc')`. Loading fresh artwork and switching parts both fail to recover.
Pre-existing.
Change: build restored state locally and commit once nothing can throw; on failure reset rather
than continue, and never show `.message`. Effort: **M**.

**T0-7. Cancel does not stop a rebuild inside a part — 140.4s measured.** _(High)_
Lens: `edge-cases` T0-5. On a 6000-region wheel: clicked at t+10.2s, actually stopped at t+150.6s,
button reading "Cancelling…" the whole time while progress climbed 24%→40%. On 20k regions it was
at 9% after 100s. `throwIfCancelled()` has one call site, the top of the part loop, and its own
doc explains why more are dangerous. When the cancel finally lands, nothing on screen says so.
Pre-existing.
**This one has a release-notes consequence.** `[Unreleased]`'s "A long rebuild can be cancelled"
bullet is true for a multi-part build, where the between-parts check fires, and misleading for one
heavy part. The bullet needs the limit stated or the claim narrowed. Effort: **M–L**, or **S** to
stop promising.

**T0-8. Placement warnings appear only after the download, then outlive what they describe.** _(High)_
Lens: `not-ready` NR-3. A 240mm hubcap on the X1C exports with a completely silent panel; the pill
appears afterwards. The pills then survive part changes, printer changes and rebuilds — screenshot
of two pills naming "Hubcap" and a "350×320mm plate" sitting over a wheel on a 256mm bed.
Pre-existing. Effort: **S–M**.

**T0-9. The Depth panel shows numbers the app is not using, N warnings at a time.** _(High)_
Lenses: `walkthrough` F2, `maker-workflow-review` M9. Typing `0` into the single Default depth
field produces one identical warning per color (four at once, `Dismiss all (5)`) and leaves every
field reading `0.00 mm` while the app cuts `0.20 mm`. There is no way to read the applied value off
the screen. Pre-existing. Effort: **S**.

**T0-10. A `parts.json` that parses but is not an array wedges the app on "Loading assembly…".** _(Medium)_
Lens: `edge-cases` T0-7. `asmKindCanAutoLoad` calls `.find` on a non-array, which throws inside the
render, leaving the panel on its initial text with no message.
**Partly introduced by #227**: before it, this state showed manual add buttons. Effort: **S**.

**T0-11. An unknown `printerId` restores a blank picker while export uses the default bed.** _(Medium)_
Lens: `edge-cases` T0-8. Silent, and the bed is the thing placement is verified against. Pre-existing. Effort: **S**.

**T0-12. Design radius accepts 0 and negatives.** _(Medium)_
Lens: `edge-cases` T0-9. 0 makes every cut fail with Export still green; negatives build silently as
if positive. The hubcap's own parameter clamps exemplary, in the same panel. Pre-existing. Effort: **S**.

## 4. Conflict ledger

**C1 — The part-switch confirm: is it missing, or is it a false alarm?** _(the cycle's headline
collision, and it is with the previous cycle)_

- 2026-08-08 **A2** filed it as a defect that switching part shape carried artwork across **with no
  confirmation**, and asked for one.
- This cycle, `walkthrough` **F1** files the confirm itself as a High: it fires on every switch,
  says "Switching parts will clear the currently loaded ones", and then loses nothing the user can
  see. `edge-cases` T1-5 and `not-ready` NR-6 land on the same string independently.
- **Resolution: both are right, and the string is the loser.** A2's repro was Wheel→Disc, which
  took the flat branch and never confirmed; assembly→assembly always did. Removing Disc made every
  switch confirm, which closed A2 mechanically without anyone writing a confirm. What is left is a
  modal whose words describe _parts_ — which are cleared and silently reloaded — to a user who
  reads it as their _artwork_, which survives. The fix serves both findings: say what actually
  happens to the design, or drop the modal, having established that nothing the user values is
  lost. **Do not simply delete it** without re-checking A2's case, or the next cycle re-files A2.

**C2 — The Advanced panel: C4 (2026-08-08) is re-opened by this release.**

- C4 resolved to keep the panel and reword it, explicitly because it is "a genuine recovery path
  for a bad or custom mesh, and removing it would leave a user with a mis-detected face no way
  out".
- Custom meshes were removed in #227. Every mesh now comes from the shipped manifest, fingerprinted
  against a verified pose. The "bad mesh" half of that justification no longer exists.
- **Resolution: the panel stays for this release, C4's remedy (A4, reword the summary) still
  stands, and the deletion question is re-opened for the next `subtract` or `bloat` cycle** with
  the new premise recorded. `assumptions`' dissent in C4 is stronger than it was.

**C3 — `edge-cases` wants more validation; the maker lens wants fewer interruptions.**

- `edge-cases` files nine Tier 0s, most asking for a guard, a clamp or a message.
- The maker lens's own High findings are about too much on screen already (T1-1).
- **Resolution: no real conflict, and it is worth saying why.** Every `edge-cases` guard fires on a
  state the user cannot currently detect at all — a silent wrong export, a destroyed session, an
  unclamped depth. None adds a control or a step to the happy path. The maker complaint is about
  the _resting_ density of the panel. Both can be satisfied at once, and T1-1 is the item that does
  it.
